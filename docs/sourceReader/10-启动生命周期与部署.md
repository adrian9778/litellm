## 1. 启动

## 2. 进程模型

```
worker[0..N): litellm.proxy.proxy_server:app (uvicorn/gunicorn)
├── uvicorn-manager
├── Prometheus 指标 (:9600)
├── collector (可选)
├── Dockerfile (registry)
├── HTTP: :4000
└── TCP/10800 (debug)
```

- `num_workers=1` 时，`gunicorn` 不启用，使用 `uvicorn` 原生。
- `--num_workers N` 且 `--reload=False`，用 `gunicorn` 的 `--worker-class`。
- `--max_requests_before_restart`：每个 worker 在 N 次请求后重启（内存增长控制）。
- `--timeout_graceful_shutdown`: `60s`。
- 对于 `--reload`，Gunicorn 的 `--reload` 用 `uvicorn.reload` 替代。

### 2.1 优雅停机

`build_graceful_shutdown_uvicorn_worker(timeout_graceful_shutdown, max_request_header_size)`：
- `timeout_graceful_shutdown` 是兜底，**超时后强杀**。
- `SIGTERM` 到 worker 的中间态：`max_request_header_size` 保护 db。
- **不能**：健康探针，Uvicorn 不关心。

### 3.1 Docker 入口点

`docker-entrypoint.sh` 由 `$LITELLM_COMPONENT` 分派（proxy, gateway, backend）：
```
case "$LITELLM_COMPONENT" in
  proxy: python -m litellm.proxy.proxy --port=4000 ...
  gateway: python -m litellm.proxy.proxy --port=4000 ...
  backend: uvicorn litellm.runtime.backend.main:app -worker ...
  prometheus: prometheus ...
esac
```

### 3.2 docker-compose

`docker-compose.quickstart.yml` 里面有：postgres + redis + proxy。
`docker-compose.tracing.yml`：加 `tracing-config.yaml` 的 otel config。

### 3.3 PRISMA env

`DATABASE_URL` 或 `DATABASE_HOST` + `DB_...`！

## 4. 启动检查清单

1. `LITELLM_MASTER_KEY` 无，就报错（`master_key_boot_verdict`）
2. `DATABASE_URL` 无，就拒绝（`db_url_settings`）——用 OIR 或本地 DB
3. `Redis` no，都是用 local cache。
4. `python -m sys.settings` 无异常。

## 5. 测试启动

`litellm/proxy/dev_config.yaml` + `--config` 可指定非生产。
`make -C litellm run_proxy` 可启动。
