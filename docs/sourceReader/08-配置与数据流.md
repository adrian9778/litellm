# 配置与数据流

> **代码基准**：`main@e46fe2e2dc1bdd19f7953bd47dc3d770876ac74e（工作区干净）`；核实日期：2026-11-17。
> **范围**：LiteLLM 的配置来源（config.yaml / 环境变量 / DB）、`litellm/settings` 配置流、`litellm_params` 在 model_list 中的传递、以及 router 的 model_list 数据流。
> **前置**：U6 已确认 Proxy Server；U03 已确认 `Resolved.of()` 解析 `model_list`。

## 0. 结论速览

LiteLLM 的配置有**三条流**：
1. **`litellm.yaml`（主配置）**：由 `litellm/proxy/proxy_server.py 7087` `load_config` 读取，分为 `general_settings`/`litellm_settings`/`model_list`/`api_key_management`/`key` 等块；`proxy_config_reload_interval_seconds` 控制热重载（`_configured_db_callbacks` + `load_config`）。
2. **环境变量**：`LITELLM_*` 前缀（如 `LITELLM_MASTER_KEY`, `DATABASE_URL`, `LITELLM_CONFIG`），在 `litellm/proxy/proxy_server.py 1553` 等地方 `os.getenv`。
3. **DB（Prisma `LiteLLM_SpendLogs`/`LiteLLM_Models`/`LiteLLM_ApiKeys`）**：DB 覆盖的 `general_settings`（`LITELLM_SETTINGS_SAFE_DB_OVERRIDES`）+ 模型在 DB 的 key 管理。

**数据流**：
```mermaid
flowchart LR
  A[client request] --> B[Proxy]
  B --> C[load_config settings]
  C --> D[ModelList from yaml/DB]
  D --> E[Router (Aligned)]
  E --> F[Provider]
```

使得配置到 model_list 的映射走 `litellm_params`（`litellm/types/litellm_params.py`）：包含所有参数。

## 1. 配置来源与加载

### 1.1 `litellm.yaml`

核心架构在 `litellm/proxy/_types.py 2578` `ConfigGeneralSettings`：
```python
class ConfigGeneralSettings(LiteLLMPydanticObjectBase):
    """Documents all the fields supported by `general_settings` in config.yaml"""
    access_group_rules, use_spend_logs_ledger, request_tag_mappings, completion_model, ...
```
结构为：
| 块 | 内容 | 示例文件 |
|---|---|---|
| `model_list` | model_name + litellm_params（api_key, models, max_tokens, stream 等） | `dev_config.yaml`/`load_balancer.yaml` |
| `general_settings` | master_key, workers, health_checks, endpoint, db 参数, ... | 见 `ConfigGeneralSettings` |
| `litellm_settings` | callback, log_config, api_version, ... | `opentelemetry_config.yaml` |
| `api_key_management` | api keys + key 轮转 | `simple_config.yaml` |
| `router_settings` | routing_strategy, num_retries | `load_balancer.yaml` |
| `additional_settings` | prompt/large-inline ... | `oai_misc_config.yaml` |

### 1.3 DB

`DB override`：`LITELLM_SETTINGS_SAFE_DB_OVERRIDES` 定义了可以从 DB 里设的 key（`proxy_server.py` metadata）。DB 里的主模型设置是 `litellm/proxy/db/model_insights_tasks.py` + `db_url_settings.py` 加 `PrismaManager.setup_database`。

## 2. 热重载

`proxy_config_reload_interval_seconds` 控制：
```
if (reload_interval is not None and elapsed > reload_interval): load_config router/set
```
（`load_config` 方法，`proxy_server.py 7087`）。注意 `use_background_health_checks` 读到这个值。

## 3. `litellm_params` 数据流

每个 model 实体的 `litellm_params` 结构是 `litellm/types/litellm_params.py GenericLiteLLMParams`：
```
model_list --- (model -> deployment)
├── deployment_id
├── litellm_params (json)
│   ├── api_key: str
│   ├── max_tokens: int
│   ├── models: str
│   ├── stream: bool
│   ├── extra_body: dict
│   └── metadata etc
```
在 `litellm/main.py 5895` 最终解析为 `|| kwargs.get("custom_llm_provider")`。

## 4. 配置到请求的映射

在 `common_request_processing.py 3810` `base_process_llm_request` / `litellm/proxy/route_llm_request.py`:
- `_router_default_litellm_params` — 合并通用 litellm_params
- `_candidate_deployment_litellm_params` — 候选部署的 litellm_params
- `_validated_deployment_litellm_params` — 验证（不能传 deploy `None`）
- 把 `litellm_params` 注入到 `router_params` 里。

`litellm/main.py` 的 `llm_provider` — 解析成 `openai`/`anthropic`/`bedrock`/...。

## 5. 几个重要的配置字段

| 字段 | 默认 | 元 | 代码锚点 |
|---|---|---|---|
| `proxy_config_reload_interval_seconds` | 0 | 不重载 | `proxy_server.py 8840` |
| `use_spend_logs_ledger` | true | 是否用 SpendLogs 做账 | `ConfigGeneralSettings` |
| `completion_model` | null | 默认模型 | `proxy_server.py 7889` |
| `disable_spend_logs` | false | 关掉花钱 | `main()` |
| `workers` | 1 | gunicorn workers | `proxy_cli.py 112` |
| `max_requests_before_restart` | 0 | worker 重启 | `proxy_cli.py` |
| `timeout_graceful_shutdown` | 60 | 优雅停机 | `graceful_uvicorn_worker.py` |
| `request_tag_mappings` | Null | W3C baggage | `request_tag_mappings.py` |
| `access_group_rules` | Null | 团队 ACL | `access_group_rules.py` |
